# 正式环境接口测试报告

测试日期：2026-10-19，Asia/Shanghai。环境：`https://documenter.perfumestore.xin`。Apifox：文枢团队 / 文枢项目 / main，正式环境 ID `49499740`。

## 结论

核心文档处理及 AI 闭环通过，但存在 **1 个 P0 缓存隔离缺陷**，表现为两条安全断言失败：匿名请求可从 ESA 缓存获取用户资料及文件列表。正式环境不能据此判定验收通过。

## P0：受保护响应被 ESA 缓存并向匿名请求返回

**观察证据：**

| 不携带 Authorization 的请求 | 实际结果 | 预期 |
| --- | --- | --- |
| `GET /user/me` | HTTP 200，code=0，含用户资料结构 | HTTP 401 |
| `GET /file/list?page=1&size=1` | HTTP 200，code=0，含文件列表结构 | HTTP 401 |
| `GET /user/me?__codex=<唯一值>` | HTTP 401，code=401 | HTTP 401 |
| 文件列表加唯一查询参数 | HTTP 401，code=401 | HTTP 401 |
| `HEAD /user/me` | HTTP 200 | HTTP 401 |
| 唯一地址的匿名 HEAD 对照 | HTTP 401 | HTTP 401 |

标准 `/user/me` 响应包含 `Server: ESA`、`Age: 42120`，并在重复请求中返回相同的 X-Request-ID。响应同时带有 `Cache-Control: no-cache, no-store, max-age=0, must-revalidate`，却仍被边缘缓存返回。客户端发送 no-cache 也未解决。报告仅保留响应结构、状态及缓存事实，不复制用户资料值或文件列表正文。

**影响：**匿名用户可能获取已缓存的用户资料及文件列表；不同登录身份还可能收到同一缓存对象。其他下载、预览等受保护路径是否被同样缓存尚未逐项验证，不能排除。

**定位：**证据指向 ESA 缓存策略或缓存键隔离失效；是否存在强制缓存规则、Authorization 被忽略等具体原因，需要核查 ESA 控制台。唯一地址返回 401 说明绕过既有缓存时服务端能拒绝匿名访问，但不能据此证明所有鉴权路径均无问题。

**处理顺序：**

1. 在 ESA 为全部动态 API 路径设置不缓存，检查是否有覆盖源站 no-store 的强制缓存规则。
2. 清除已存在的受保护响应缓存；仅修改后续规则不足以清理旧对象。
3. 复测标准 URL 的匿名、无效 Token、退出后 Token、用户 A/B 隔离，不使用随机参数掩盖问题。
4. 同时核查文件下载、页面图片和导出路径；重新登录不等于缓存已清除。

不得将增加 `__codex` 参数当作修复。它只用于本轮测试避开旧缓存。

Apifox 独立复现报告：[26881189](https://app.apifox.com/link/project/8905406/api-test/test-report/26881189)。项目中已保存场景“正式环境 · 匿名鉴权与缓存隔离”（ID `8863993`），使用 HEAD，不需要账号密码、不收集响应正文。该场景当前预期失败；修复后两个步骤都应通过。
