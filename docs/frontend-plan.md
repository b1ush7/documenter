## 2. 技术选型

### 2.1 推荐方案

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | **Vue 3 + TypeScript** | 组合式 API 配合 TypeScript 的类型推导最顺；团队若更熟 React 则换 React，本文档其余结论不变 |
| 构建 | **Vite** | 开发态冷启动快；产物是纯静态文件，便于分离部署 |
| UI 组件库 | **Element Plus**（Vue）/ **Ant Design**（React） | 表格、分页、上传、时间线等本项目高频组件齐全；中文文档完善 |
| 状态管理 | **Pinia**（Vue）/ **Zustand**（React） | 本项目状态简单，只有「登录态」需要全局共享，不需要重型方案 |
| HTTP | **Axios** | 拦截器是实现「401 自动刷新」最自然的位置 |
| 路由 | 框架官方路由 | 配合守卫做登录态与管理员权限拦截 |
| 代码规范 | ESLint + Prettier | —— |

### 2.2 为什么不选其他方案

| 方案 | 不选的原因 |
| --- | --- |
| 服务端渲染（Next.js / Nuxt） | 本项目是登录后使用的内部工具，没有 SEO 与首屏性能诉求；SSR 会引入 Node 服务端部署成本，与「纯静态文件 + 后端 API」的简单形态不匹配 |
| 后端内嵌模板（Thymeleaf）+ 少量 JS | 文件预览、表格编辑、对话这类交互密集的界面用模板渲染会迅速失控，最终仍然要写大量 JS |
| 低代码 / 表单引擎 | 本项目页面数量不多（约 15 个），定制化程度高（预览渲染、版本对比），低代码的约束会成为负担 |

### 2.3 后端已就绪的支撑

前端不需要等后端改造，以下能力已经具备：

- **纯 REST + 统一响应体**，无需处理服务端渲染的会话状态
- **Token 双令牌 + 刷新接口**，支持无状态前端
- **接口按页面组织好的联调文档**（`docs/frontend-api-by-page.md`，覆盖全部端点）
- **原始图片字节流的预览接口**，便于前端直接渲染
- **请求追踪头**（`X-Request-ID`），前后端可按同一次调用对日志

## 3. 必须优先实现的三个前端机制

这三项不做，后面每个页面都会返工。建议在第一个页面之前先落地。

### 3.1 401 自动刷新 Token

```
任意请求收到 HTTP 401
  ├─ 有 refreshToken → POST /user/refresh
  │    ├─ 成功 → 覆盖本地双 Token，重放原请求（仅一次）
  │    └─ 失败 → 清空 Token，跳登录页
  └─ 无 refreshToken → 跳登录页
```

四个必须处理的细节：

1. **刷新要加互斥**。多个请求同时 401 时只允许一个真正去刷新，其余等待其结果。
   并发刷新会让彼此的 Refresh Token 互相作废 —— 因为轮换是单次有效的。
   这是最容易踩的坑，表现是「偶发地被踢出登录」。
2. **只重放一次**。重放后仍 401 就跳登录页，避免无限循环。
3. **不要只靠定时刷新**。设备休眠、时钟漂移都会让它失准，以 401 驱动为主路径。
4. **多标签页同步**。多个标签页各持一份 Token 会互相覆盖，建议
   `localStorage` + `storage` 事件同步。

Token 有效期：Access 15 分钟、Refresh 7 天。

### 3.2 统一错误提示

后端所有失败都会给出可读的 `msg`，**前端应优先直接展示它**，而不是自己按
状态码拼文案。举两个例子：

- 上传 415 时 `msg` 会说明具体原因（如「检测到旧版 Office 二进制格式
  （.doc/.xls/.ppt），当前仅支持 .docx/.xlsx，请先另存为新格式」）——
  这是前端无论如何都拼不出来的信息量。
- 版本冲突 409 时 `msg` 会带上当前实际版本号。

**404 的特殊约定**：后端对「他人的资源」统一返回 404 而不是 403（避免枚举 ID）。
因此前端对 404 **不要提示「你没有权限」**，应统一提示「资源不存在或已删除」。
否则等于把「该 ID 真实存在」这件事泄露出去。

### 3.3 预览与下载必须锁定同一版本

这是 TODO 4.3 第三条的硬要求：**避免预览与导出内容不一致**。

前端必须遵守：

- 预览、下载、恢复、编辑全部使用**路径里带 `versionNo` 的接口**
  （`/file/{fileId}/versions/{versionNo}/...`），而不是「当前版本」的简写接口
  （`/file/{fileId}/download`）
- 页面上的**版本切换器是唯一状态源**：切换版本时预览、编辑面板、下载按钮
  必须同时切到该版本，不能各自缓存
- 版本不存在时后端返回 **404 而不是回退到最新版本**。
  这是刻意的：静默回退会让用户看到与预期不同的内容却毫无察觉

后端侧已由测试锁住该契约（`PreviewVersionConsistencyTest`）：
预览元信息、预览图片、版本下载三条路径都只按明确版本解析。

## 4. 部署方式

### 4.1 与后端分离部署（推荐）

前端构建产物是纯静态文件，与后端进程解耦：

```
构建：npm ci && npm run build   →  dist/
部署：把 dist/ 交给静态服务器或 CDN
```

Nginx 参考配置：

```nginx
server {
    listen 80;
    server_name documenter.example.com;

    root /var/www/documenter/dist;
    index index.html;

    # 单页应用：所有未命中静态文件的路径都交给 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端接口反向代理，避免浏览器跨域
    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 上传大文件需要放宽限制，默认 1m 会让 50MB 的上传直接 413
    client_max_body_size 64m;
}
```

**为什么用反向代理而不是让前端直连后端**：同源可以省掉 CORS 配置与
预检请求，也不需要在 Cookie/Token 策略上做额外约定。

**`client_max_body_size` 必须放宽**。默认 1MB 会让上传在 Nginx 层就被拒绝，
返回的 413 是 Nginx 的 HTML 页面而不是后端的统一 JSON ——
前端解析会失败，且排查时容易误以为是后端问题。后端上传上限是 50MB，
这里建议留出余量配 64m。

### 4.2 也可与后端同源部署

若希望更简单，把 `dist/` 内容放进后端的 `src/main/resources/static/`，
由 Spring Boot 直接提供。代价是：

- 前端每次改动都要重新打包后端，失去独立发布的便利
- 需要处理单页应用的前端路由回退（Spring Boot 需配置把未知路径转发到 `index.html`）

**建议仅在本地联调或演示环境使用这种方式。**

### 4.3 环境变量与 API 地址

| 变量 | 用途 |
| --- | --- |
| `VITE_API_BASE_URL` | 后端基地址。分离部署时若已用 Nginx 反代 `/api/`，填 `/api` 即可 |

**注意不要在前端放任何密钥**。前端产物是公开可下载的，所有校验必须在后端完成
（当前后端已经是这个形态：所有归属校验都在服务端，前端传不了 userId）。

### 4.4 构建与缓存

- 产物文件名带内容哈希（Vite 默认行为），可对 `assets/` 设置长缓存
- `index.html` **不要缓存**（`Cache-Control: no-cache`），否则发版后用户仍拿到旧入口
- 版本切换类接口的响应已带 `Cache-Control: private, max-age=3600`，
  预览图片按「内容摘要 + 页号 + DPI」缓存，同一版本重复请求不会重复渲染

## 6. 联调前的准备

1. **后端接口文档**：`docs/frontend-api-by-page.md`（按页面组织，覆盖全部端点）
2. **验证码获取**：开发环境验证码打印在**服务端日志**（`[Mock 验证码]` 开头），
   需向后端索取；接入真实短信后发送接口会改为统一话术
3. **时间格式**：后端返回 ISO-8601 本地时间且**无时区后缀**（如 `2026-10-12T10:00:00`），
   按本地时间解析
4. **文件下载与页面预览返回二进制流**，不是统一 JSON，需用 `response.blob()` 处理
5. **`balance` 是 `DECIMAL(20,6)`**，建议按字符串接收后再格式化，避免精度问题
